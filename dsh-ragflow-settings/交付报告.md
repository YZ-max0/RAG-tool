# 交付：RAGFlow 会话级知识库检索

状态：**ready · 已上线**（v0.4.0：插件页内配置连接，无需环境变量）

## 0. 本轮新增：插件页直接配置连接

v0.3.0 之前，用户必须先在机器上设好 `RAGFLOW_API_KEY` / `RAGFLOW_BASE_URL`
才能用，否则插件页看到的永远是空列表——对普通用户等于不可用。

v0.4.0 在卡片顶部加了「连接到 RAGFlow」表单（地址 / API Key / 超时）+「测试连接」：

- 连接未通过时知识库勾选区锁住，避免对着必然失败的列表点。
- 测试可用**未保存**的参数，用户不必先保存再去对话里试错。
- 读取配置的接口只返回掩码（如 `ragf…mHzA`）与来源，从不回传明文。

### 凭据三级降级（实测）

| Host 环境 | Key 存放 | 实测结果 |
| --- | --- | --- |
| 有 `credentials` 服务 | `ragflow-config.json` 只写 `{"apiKeyRef":"ragflow"}` | ✅ 文件无明文，`source=credential-provider`，测试连上 5 个库 |
| 无凭据服务 | 内联 `{"apiKey":"…"}` | ✅ 接口仍只回掩码 `ragf…7890` |
| 都没有 | 回落 `RAGFLOW_API_KEY` 环境变量 | ✅ `source=windows-user-environment`，5 个库 |

优先级 **插件页 > 环境变量 > 默认值**；改版前靠环境变量跑通的部署无需改动。
清空页面里的 Key 会回落环境变量（实测：坏 Key → 401，清空后恢复 `total=20`）。
地址会做 http/https 校验，超时限定 1000–300000ms（越界返回 400）。

## 1. 上一版（v0.3.0）的问题

上一版交付里，输入框旁边的「知识库」选择器写 `ragflow-session-selection.json`，
但没有任何代码读它 —— `ragflow-mcp/server.cjs` 只读 `ragflow-settings.json`。
所以那个选择器勾什么都不影响检索。

根因是架构，不是笔误：

1. 一个 Host 只 spawn 一个 stdio MCP 子进程，所有会话共用（实测 PID 单一，父进程即 Host）；
2. `@deepseek-ai/dsh-mcp-client` 的 `createTransport()` 用
   `buildChildEnv(config.env) = { ...scrubbedParentEnv(), ...extra }`，
   `scrubbedParentEnv()` **丢弃 `DSH_*` 变量**，桥接进程拿不到会话身份；
3. 会话 id 也不在 MCP 协议的调用参数里。

## 2. v0.3.0 的做法

把检索从 MCP 搬到**宿主工具**。宿主工具的 `execute(args, exec)` 带
`exec.agent.id`（类型 `SessionId`），就是调用方会话 id —— 与
`ragflow-session-selection.json` 的键同形（`session-<uuid>`）。

`@local/dsh-ragflow-settings` 现在同时提供：

- 2 个工具：`ragflow_list_datasets` / `ragflow_retrieval`（无 `mcp__` 前缀）
- 4 条路由：`GET/POST /ragflow-settings/state|selection|session`
- 浏览器半边：设置页卡片 + 输入框旁的会话选择器

`~/.dsh/cordis.patch.yml` 里 `mcp-ragflow` 那一行加了 `disabled: true`
（保留 `ragflow-mcp/server.cjs` 给 Codex / Claude Desktop 这类自己 spawn 的客户端）。

## 3. 检索范围优先级

`dataset_ids` 省略时：**显式参数 > 本会话选择 > 全局默认 > 全部可访问**。
空数组是真实选择（本会话不检索），不会退回全局。
返回值带 `dataset_source`（`argument`/`session`/`global`/`all`）与 `dataset_ids`。

## 4. 验收实证

### 4.1 单元级（直接驱动 `execute`，真实 RAGFlow）

```

[session-A override]        dataset_source=session  ids=[<会话自己的库>]  total=0
[session-B override]        dataset_source=session  ids=[<会话自己的库>]  total=0

[session-D 空数组]           ERROR this conversation selects no knowledge base; tick at least one to search
[无 agent id（宿主上下文）]   dataset_source=global   total=26
[显式 dataset_ids]           dataset_source=argument ids=[<指定的库>] total=12
```

### 4.2 集成级（真实独立 Host）

先在一个临时 profile 起的独立 Host 上验证：插件行进入组合树、路由 200、工具注册成功。

### 4.3 上线后回归（重启后的桌面 Host）

桌面 Host 重启、真实加载本版之后，用真实工具调用验证会话选择即时生效：

| 操作 | 工具返回 |
| --- | --- |
| 本会话选库 A | `dataset_ids=[<库 A>] dataset_source=session total=5` |
| 改选库 B | `dataset_ids=[<库 B>] dataset_source=session total=12` |
| 改回原值 | 恢复原状 |

两次切换之间**没有重启 Host**，说明选择是每次调用实时读取的。
同时确认旧的 `ragflow-mcp` 子进程已不再被 spawn（无孤儿进程），
两个宿主工具均在线、5 个知识库正常返回。

## 5. 已知限制

1. **升级到本版需要重启一次 Host**（本次已完成）。工具在 `apply()` 里注册，
   包清单与 bundle 只在启动时读取；会话勾选的**内容**不需要重启，每次调用实时读文件。
2. **MCP 版工具与宿主版工具同名**。所以旧 `mcp-ragflow` 行必须保持 `disabled: true`，
   否则会重名冲突。要给第三方 MCP 客户端用桥接，直接跑 `server.cjs` 即可，与 Harness 无关。
3. **`exec.agent.id` 的类型契约来自 `@deepseek-ai/dsh-agent` 的 `Agent`**
   （`readonly id: SessionId`）。这是 Host 侧公开类型；取不到时工具退回全局默认，
   不会报错（见 3.1 的「无 agent id」一行）。
4. 设置页卡片保存的是**全局默认**，会话选择器保存的是**本会话**；
   两者互不覆盖，这是有意设计。
5. **没有 DSH 凭据服务时，Key 以明文存放在 `ragflow-config.json`**。接口不会回传它，
   但能读到该文件的人就能读到 Key。有凭据服务的 Host 不会有这个问题。
6. **只支持一个 RAGFlow 实例**（一处地址一套 Key）。多环境需求暂不支持。

## 7. 环境陷阱（复发过）

1. **DLP 加密**：PowerShell / 普通 node 写出的文件带 `%TSD-Header-###%` 头，
   Electron 读到即 `SyntaxError`。所有安装文件必须由 Harness 写工具写出。
2. **`Copy-Item` 复制 `package.json` 到 profile 会被加密**（本次实测复现：
   `copy` 后 `--dump-config` 报 `Unexpected token '%'`），必须用 Harness 写。
3. `dsh --profile desktop --dump-config` 被拒（desktop 由 Electron 独占管理），
   验证组合树要另建临时 profile。
