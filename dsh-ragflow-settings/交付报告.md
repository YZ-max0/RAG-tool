## 7. 关键实现点

**宿主半边**（`lib/index.js`）：`inject = ['webServer']`，注册两个 exact 路由，全部包在 `ctx.effect` 里。
凭据先读 `process.env.RAGFLOW_API_KEY`，取不到回退 `HKCU\Environment`（实测 DSH 进程未继承该变量）。
写盘用临时文件 + `rename`，桥接不会读到半截文件。

**浏览器半边**（`lib/client.js`）：`window.__ModuleLoader__.load({id, factory})`，factory 内 `ctx.locale.register` + `ctx.slots.inject('plugins.item', ...)`，与官方 `dsh-client-ui-settings-web-search` 同构。
**未 require `dsh-client-ui-primitives`**（该包在 asar 内不存在，且官方 practices 明确禁止），自写控件 + 只用 `--dsw-alias-*` 主题 token。

## 8. 必须报告的两个环境陷阱

1. **本机 DLP 会加密 PowerShell / 普通 node 写出的文件**：`%TSD-Header-###%` 头，Electron 进程读到乱码，`JSON.parse` 直接抛错。
   首次安装正是踩了这个——`package.json`、`cordis.patch.yml`、locale 全部被加密导致 profile 无法启动。
   **只有 Harness 进程自己写出的文件是明文。** 我已全部用 write 工具重写，重装后 6 个文件在 Electron 进程中读取均为正常明文。
   （建议：以后凡是装到手写 profile 的文件，都走 Harness 侧写入，别用 PowerShell 复制。）
2. `dsh --profile desktop --dump-config` 被拒（`profile "desktop" is managed exclusively by the Electron application`）；改用临时 profile `verify` + `dsh --profile verify --dump-config` 才拿到组合结果。
